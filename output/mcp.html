出典: anthropic.com/news/model-context-protocol

なぜ必要？

ツールごとに専用の配線を作る

AIの種類 × ツールの数 = 組み合わせの数

AIやツールが増えるたび、組み合わせの数だけ連携コードが必要になる

MCPという共通規格に合わせる

AI ⇄ MCP ⇄ ツール

一度MCPに対応すれば、どのAIからでも同じように使える

従来はAI側とツール側それぞれで専用の連携コードを書く必要がありました。MCPは話し方を1つに揃えることで、この組み合わせの手間を減らします。

どう動く？

1

MCPサーバーを立てる

ツール側に窓口を用意する

2

クライアント（AI側の窓口アプリ）が接続する

Claude Code などが、使えるツール一覧を受け取る

3

AIがツールを呼び出す

必要なときだけ、許可を得て実行する

やり取りの手順をMCPが共通化しているので、サーバーとクライアントの組み合わせが変わっても仕組みは同じです。

ターミナル

$ claude mcp add github -- npx -y @modelcontextprotocol/server-github

Added MCP server "github"

↑ この1行で、AIがGitHubを見に行けるようになる

.mcp.json

{ "mcpServers": { "github": { ... } } }

AIが書くコードのしくみそのものは変わりません。変わるのは「見える範囲」で、追加したMCPサーバーの分だけ参照できる情報が広がります。

よくある勘違い

✗ MCPを追加すればAIが自動で何でもやってくれる

✓ 実行の前に、多くの場合ユーザーの許可を求められる

ファイル削除など取り返しのつかない操作を、確認なしに実行させないための仕組みです。

✗ MCPはClaude専用のしくみ

✓ 誰でも使えるオープンな規格

同じ規格に対応してさえいれば、他のAIアプリやツールからも使えます。

出典: modelcontextprotocol.io/docs/getting-started/intro

AIへの伝え方

BEFORE

「GitHubのIssueを見て直して」

→ AIはGitHubに接続できず、憶測で答える

AFTER

「GitHub用のMCPサーバーを.mcp.jsonに追加してから、Issueを見て直して」

→ 実際のIssueの内容を見て答えてくれる
