Model Context Protocol（MCPの正式名称） .mcp.json（接続先を書く設定ファイル） ブラウザ操作 ファイル操作

2024年11月にAnthropicが発表した規格です（2026年9月時点）。「サーバー」という名前ですが、遠くの大きなコンピュータではなく、多くは自分のPCで動く小さなプログラムです。

出典: anthropic.com/news/model-context-protocol

なぜ必要？

ツールごとに専用の配線

AI3種 × ツール3種で9本。増えるたびに掛け算で増える

MCPという共通規格に合わせる

それぞれがMCPに1本ずつ。足し算で済む

従来はAI側とツール側それぞれで専用の連携コードを書く必要がありました。MCPは話し方を1つに揃えることで、この掛け算を足し算に変えます。

出典: modelcontextprotocol.io/docs/getting-started/intro

どう動く？

1

公開されているサーバーを登録する

claude mcp add playwright -- npx -y @playwright/mcp@latest

2

つながったか確かめる

claude mcp list

AI側が、使えるツールの一覧を受け取る

3

AIがツールを呼び出す

browser_navigate を許可しますか？

初めて呼ぶときは許可を求められる

やり取りの手順をMCPが共通化しているので、サーバーとクライアントの組み合わせが変わっても仕組みは同じです。

ターミナル

$ claude mcp add playwright -- npx -y @playwright/mcp@latest

Added stdio MCP server playwright

$ claude mcp list

playwright ✔ Connected

↑ この2行で、AIがブラウザを動かせるようになる

.mcp.json

{

  "mcpServers": {

    "playwright": {

      "type": "stdio",

      "command": "npx",

      "args": ["-y", "@playwright/mcp@latest"]

    }

  }

}

上のコマンドは自分専用の設定に保存されます。この .mcp.json のようにチームで共有したいときは --scope project を付けます。AIが書くコードのしくみは変わらず、変わるのは「AIができること」の範囲です。

よくある勘違い

✗ 一覧に出てくるMCPサーバーは、どれも安全

✓ 自分のPCの中でプログラムが動く。提供元を確かめてから入れる

ローカルのMCPサーバーは、AIが呼ぶたびに自分のPCでプログラムを実行します。だからClaude Codeは、他人のリポジトリに書かれた設定を初回に必ず承認させます。

✗ MCPを追加すればAIが自動で何でもやってくれる

✓ 初めて呼ぶときは許可を求められる

ただし一度許可すると以後は省かれることがあります。何を許可したかは自分で把握しておく必要があります。

✗ MCPはClaude専用のしくみ

✓ 誰でも使えるオープンな規格

同じ規格に対応してさえいれば、他のAIアプリやツールからも使えます。

出典: code.claude.com/docs/en/mcp-quickstart（2026年9月時点）

AIへの伝え方

BEFORE

「作ったログイン画面、ちゃんと動くか見て」

→ AIは画面を開けず、コードから憶測で答える

AFTER

「playwright で http://localhost:3000 を開いて、ログインを試して結果を教えて」

→ 実際にページを開いて、その結果を答える

これだけ覚えればOK

次に調べる

スコープ（local / project / user）
