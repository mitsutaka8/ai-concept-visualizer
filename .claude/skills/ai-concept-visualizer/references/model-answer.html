環境変数

プログラムの外側に置いておく、人に見せたくない設定値のこと。

プログラムを動かす環境が持っている「名前と値」の一覧

API_KEY=sk-abc123456789

DATABASE_URL=postgres://localhost/app

プログラムは「名前」で取り出す

process.env.API_KEY

開発中は自分のPC

.env に書いておく

本番はデプロイ先

管理画面から同じ名前で登録する

APIキー（外部サービスの合言葉） パスワード データベースの接続先

.env は値を置くための一手段であって、環境変数そのものではありません。

なぜ必要？

コードに直接書く

apiKey = "sk-abc123..."

コードを GitHub に上げた瞬間、鍵も一緒に公開される

環境変数にする

apiKey = process.env.API_KEY

コードには置き場所だけ。鍵は手元に残る

APIキーは、他人に使われると料金だけこちらに請求されます。だから外に出す必要があります。

出典: 12factor.net/ja/config

どう動く？

1

値を用意する

API_KEY=sk-abc123

手元なら .env、本番ならデプロイ先の管理画面

2

読み込み役が環境変数に入れる

node --env-file=.env app.js

.env は放っておいても読まれない。ここが抜けやすい

3

名前で呼び出す

process.env.API_KEY

値そのものはコードに出てこない

2 の読み込み役は、Node.js 20.6 以降なら --env-file、それ以外は dotenv（.env を読み込むパッケージ）が担います。本番では管理画面に登録した値が最初から環境変数として入るため、2 は不要です。

出典: nodejs.org/api/cli.html（2026年9月時点）

.gitignore した .env はデプロイ先に届かない。同じ名前をここに登録する

AI が書いたコードは「値を入れる場所」だけを用意します。中身を入れるのは自分の仕事です。エラーの文言は場面によって変わりますが、共通しているのは「値が空のまま先へ進んでしまう」ことです。

よくある勘違い

✗ .env に書けば暗号化されて安全

✓ ただのテキストファイル。誰でも中身を読める

安全なのは暗号化されているからではなく、Git（変更履歴を記録するツール）に含めず手元に留めるからです。

✗ .env も GitHub にアップする

✓ .gitignore（Gitに含めないファイルの指定）に書いて除外する

代わりに、値を空にした .env.example（共有用のひな形）を置いて「何を設定すればいいか」だけを共有します。

AIへの伝え方

BEFORE

「天気APIを使う機能を作って」

→ APIキーがコードに直接書かれることがある

AFTER

「天気APIを使う機能を作って。APIキーは環境変数で読み込む形にして、.env.example も用意して」

→ 最初から安全な形で出てくる
