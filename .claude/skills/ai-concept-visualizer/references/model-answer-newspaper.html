ENVIRONMENT VARIABLE

環境変数

プログラムの外側に置いておく、人に見せたくない設定値のこと。

秘密の値をコードに書かず、プログラムの外側に置く。これが環境変数の考え方である。ここからひとつずつ見ていく。

WHY

なぜ必要か

APIキーは、他人に使われると料金だけこちらに請求される。だから外に出す必要がある。

出典: 12factor.net/ja/config

HOW

どう動くか

読み込み役は、Node.js 20.6 以降なら --env-file、それ以外は dotenv（.env を読み込むパッケージ）が担う。本番では管理画面の値が最初から環境変数として入るため、二の段は要らない。

出典: nodejs.org/api/cli.html（2026年9月時点）

ON SITE

制作現場から

AIが書いたコードは「値を入れる場所」だけを用意する。中身を入れるのは自分の仕事である。エラーの文言は場面によって変わるが、共通しているのは「値が空のまま先へ進む」ことだ。

CORRECTION

訂正 — よくある勘違い

誤

.env に書けば暗号化されて安全

正

ただのテキストファイル。誰でも中身を読める

安全なのは暗号化されているからではなく、Git（変更履歴を記録するツール）に含めず手元に留めるからである。

誤

.env も GitHub にアップする

正

.gitignore（Gitに含めないファイルの指定）に書いて除外する

代わりに、値を空にした .env.example（共有用のひな形）を置いて「何を設定すればいいか」だけを共有する。

PROMPT

AIへの伝え方

BEFORE

「天気APIを使う機能を作って」

→ APIキーがコードに直接書かれることがある

AFTER

「天気APIを使う機能を作って。APIキーは環境変数で読み込む形にして、.env.example も用意して」

→ 最初から安全な形で出てくる

SUMMARY

これだけ覚えればOK

  1. 一

    コードには値ではなく「名前」だけを書く

  2. 二

    手元の値は .env に置き、読み込み役に読ませる

  3. 三

    .env は公開しない。本番は管理画面に同じ名前で登録する
